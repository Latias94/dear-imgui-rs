# Dear ImGui 1.93 integration audit

The comparison starts at workspace commit `5d1516f` (merged PR #93). The target is the latest maintained upstream branch pins selected on 2026-10-17. Core cimgui moves from `125f397e` to `5d7cc7e1`, and its Dear ImGui dependency from `b48d1afb` to `d88f238d`: **1.93.1 WIP**, including the 1.93.0 release and subsequent obsolete-API cleanup. Nested dependencies follow their wrapper's committed selection. See [compatibility](../COMPATIBILITY.md#021-release-train) and [migration](../IMGUI_193_MIGRATION.md).

This audit uses the release notes, complete changed native headers/implementation, generated binding differences, and unchanged consumers of changed internals. Binding generation establishes reproducibility; it does not establish behavioral compatibility.

## Source adaptations and artifact routes

All adaptations stage first-party build inputs; upstream tracked files retain their exact revisions. Native builds and the Emscripten provider call the same helpers from the maintained source inventory. Artifact identities include the adaptation version so archives compiled with older behavior are rejected.

- CTE: retain bounded Unicode lookup and fullwidth corrections in `cte-text-editor-v1`, together with current-line highlight screen-coordinate corrections. The highlight uses the fixed visible text area even during horizontal scrolling. All four upstream binary searches still use unsafe end-inclusive bounds, and the width table still misses fullwidth ranges. The old `cte-wide-glyphs-v1` fix was already superseded upstream and stays removed. TextDiff receives the three current rounding-flag names. MSVC compiles the Unicode source as UTF-8.
- ImNodes: one transform combines existing file-I/O compatibility with current rounding names for native and WASM. Draw-list channels use generated/native layouts and preserve texture/vertex-offset command state.
- ImPlot: one items/demo transform handles density, subpixel line alpha coverage, rectangle bounds and candle coordinates. Remove the unused legacy FormatSpec workaround and optional CMake bypass so maintained source routes cannot skip the adaptation.
- ImPlot3D: stage core/items/demo with one adapted internal header. Its custom line and marker renderers preserve subpixel alpha coverage before expanding geometry to one screen pixel. Native archive packaging includes exactly one corrected internal header; source crates preserve original upstream input for strict drift checks.

Exact-marker tests reject source drift or repeated application. Shared Rust/Python identity fixtures and provider preparation tests cover routing and archive compatibility; these are separate from executed native behavior tests.

## Other native implementations reviewed

- **ImGuizmo:** inspect the actual `src/ImGuizmo.cpp`, new frozen/current tripod state, rectangle correction, active 1.93 drawing branches and GraphEditor parameter changes. Rust continues to pass copied matrices and opaque native state. ImGuIZMO.quat's unchanged geometry and font/clip integration use the current native branches.
- **Test Engine:** its pin is already current. Recheck context hooks and forwarded `ItemAdd`, queue/unregister ownership, capture cancellation, and `render -> pre_swap -> present -> post_swap`. The capture bridge keeps provider/userdata copies synchronized and restores aborted presentation state.
- **Core/platforms:** trace font glyph-index production/loading, builder-owned line/corner UVs, atlas growth and managed texture feedback. Allocation/queue/feedback logic is unchanged, while `PushTexture` now rejects `WantDestroy`/`Destroyed` statuses rather than testing `WantDestroyNextFrame`. Safe texture insertion already validates the current status. `ClearPlatformHandlers` now reinstalls the four default clipboard/shell/IME service handlers; backend teardown preserves baseline and foreign service overrides. Inspect viewport initial framebuffer scale and unchanged native stack-layout patch anchors.
- **Native renderer shims:** DX12 already uses current `InitInfo` descriptor allocation. Metal's attachment support resides in its updated native implementation. Shader inputs still consume ordinary vertex UV/color; backends do not decode private atlas tables.
- **FreeType:** trace every `ImFontLoader` callback against the new table. Lookup converts codepoints with `FT_Get_Char_Index`; contains/load receive glyph indexes, and load passes them to `FT_Load_Glyph`. The same pinned implementation and core defines supply the native build and prebuilt link metadata. Local compilation/rasterization is unverified because this Windows environment lacks the FreeType SDK; existing Linux/macOS pkg-config and Windows vcpkg CI lanes compile this feature.

## Verification and limits

Executed on Windows: core 619 tests with `multi-viewport,abi-probe,stack-layout`; CTE 67; node-editor 24; SDL3 122 with all three renderers and multi-viewport; Bevy 290 with render/multi-viewport (3 skips); Test Engine 36; ImGuizmo 20; quat 3; ImNodes 25; build support 79; xtask 26. WGPU passed 111 tests (4 existing skips), Glow 90, and Ash 54. All four focused plot production probes passed. Geometry tolerances account for native approximate reciprocal-square-root normalization and screen-coordinate rounding; UV comparisons remain exact. Native shim tests and standalone DX12 WARP rendering/readback also passed.

Canonical Rust 1.95 / libclang 14 generation verified all three core profiles and 14 extension profiles. The real Emscripten provider compiled and validated 3066 exports and four nonempty artifacts, alongside the Rust import route. The full workspace check and WASM demo with all supported optional extension features, including CTE, passed. WGPU 27/28/29 with Winit and WGPU 30 with SDL checked successfully; desktop CTE/blueprint examples and 83 core/CTE doctests passed. Python tooling passed 283 tests (1 skip).

Core and ImPlot3D native archives were generated for candidate `aaa19bf`. Inspection confirmed exactly one adapted ImPlot3D internal header and matching artifact identities. Both 3D production regression tests also passed when consuming these two prebuilt archives. This verifies that package route; the complete source-package/all-profile release gate remains CI's responsibility. See [PR #94](https://github.com/Latias94/dear-imgui-rs/pull/94). Static source review and cross-target compilation are not evidence of presentation on an unavailable platform.

Two pre-existing limitations remain separate from this upgrade: ImGuizmo viewport background/foreground draw lists can fail its native hovered-window lookup, and forgotten node-editor RAII tokens can leave native scopes unbalanced. These are not claimed fixed by the new phase checks. Arbitrary external engine texture synchronization remains application-owned. No Apple/mobile native-window presentation result is claimed from this Windows audit.

The follow-up independent review corrected per-rectangle AA options, current-line highlight coordinates, and subpixel plot alpha coverage. Real production regressions failed on the earlier implementations and passed with these fixes. The affected-crate matrix then passed 1309 tests (4 skips), including Glow sampler-object and texture-parameter rendering paths; Python tooling passed 283 tests (1 skip). Release preparation sets the unified train to 0.21.0 and refreshes all four lockfiles without changing external dependencies. The updated real Emscripten provider and Rust import route also pass; no browser presentation or complete five-target release-artifact matrix is inferred from these host checks.
